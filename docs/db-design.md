# DB設計メモ（SQLite + Prisma）

最終更新: 2026-09-10

## 結論
MVPは **SQLite（リレーショナル）** を推奨。

### 理由
- 募集・応募・承認・ルーム・通報は関係性が明確（RDB向き）
- 参照整合性（FK制約）が重要
- 集計（成立率、応募率）をSQLで出しやすい
- PrismaでPostgreSQLへ将来移行しやすい

## NoSQLを見送る理由（MVP時点）
- 応募/承認状態遷移や重複防止制約の管理が複雑化しやすい
- 集計時にアプリ側処理が増えやすい

## 将来拡張
- 同時接続/データ増加が見えてきたらPostgreSQLへ移行
- Prismaスキーマはほぼそのまま流用可能
